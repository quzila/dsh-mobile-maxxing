# T2 Code / Hermes Agent の機能を DSH に追加するための設計メモ

## 対象

- T2 Code: <https://github.com/ashutoshpw/t2code>。Codex、Claude などの既存エージェントを操作する独立したアプリ。`docs/user/outside-agents.md` に OAuth 対応の MCP サーバーを公開する方法がある。
- Hermes Agent: <https://github.com/NousResearch/hermes-agent>。独立したエージェント実行環境。`website/docs/user-guide/features/` に ACP と OpenAI 互換 HTTP API の接続方法がある。

## 目標と境界

利用者は DSH の Web 画面内で両者の便利な機能を使うことを望む。両リポジトリは MIT ライセンスで公開されており、ライセンス表示を保って必要なコードを移植できる。既存の `dsh-mobile-maxxing` は DSH Web UI の表示と操作を変更するプラグインであり、外部エージェントのセッションや権限を管理する実装は持たない。実行機能は DSH サーバー側の別プラグインに、操作画面は DSH Web UI 側に実装する。

## 移植方針

DSH の既存機能を起点として、T2 Code と Hermes の実装から不足する機能を一つずつ加える。ソースを丸ごと取り込むと、T2 Code の独立した認証・RPC・イベントログと Hermes の Python ランタイムを DSH の既存状態管理と二重に運用することになる。機能ごとに元コード、データ形式、状態遷移、権限、UI を確認し、DSH の対応する境界へ移す。

| 機能群 | 参照する実装 | DSH 側の作業 |
| --- | --- | --- |
| 複数エージェント操作、遠隔接続、プロジェクト・スレッド管理 | T2 Code の server、client-runtime、RPC contract、Web UI | DSH のセッションと権限に合わせたサーバー機能と画面 |
| モデル・プロバイダー選択、承認、差分・進捗表示 | T2 Code の provider adapter と client | 既存 DSH のモデル・ツール・レビュー表示との差分を埋める |
| スキル、メモリ、コンテキスト、チェックポイント | Hermes の agent と tools | DSH のセッション・ストレージ・ツールへ移植 |
| 自動化、フック、ブラウザー、音声、MCP 等 | Hermes の gateway、agent、plugins | DSH に既存機能がある場合は再利用し、ない場合だけ追加 |

各項目は機能台帳で「DSH に既存」「移植済み」「接続で利用」「未対応」「対象外」を区別する。単に画面にボタンを追加した段階を「利用可能」としない。

## 接続を使う場合

| 対象 | 公式に確認できる接続面 | DSH 側に必要なもの |
| --- | --- | --- |
| T2 Code | OAuth 対応 HTTP MCP。プロジェクト・スレッドの取得、開始、送信、停止、モデル一覧など | MCP クライアントと OAuth、権限別の操作、スレッドの表示と状態同期 |
| Hermes Agent | ACP (stdio)、OpenAI 互換 HTTP API | ACP または HTTP クライアント、セッション継続、ストリーム・ツール進捗・中断・承認の表示 |

接続は機能移植中の暫定手段、または元の独立した実行環境を利用したい場合の選択肢。T2 Code の MCP は外部エージェントに公開する操作の一部であり、全 UI 機能を公開するものではない。Hermes の ACP はエディター用途に合わせたツールセットで、cron やメッセージ配送などは対象外。DSH には ACP サブエージェント機構があるが、一回限りの子タスク用で、中間のツール活動や継続会話を親の画面へ完全には公開しない。

## 実装順と完了条件

1. **機能台帳**: T2 Code と Hermes の公開機能を列挙し、DSH 既存機能・接続可能・追加実装が必要・提供不可を区別する。利用不可を利用可能として表示しない。
2. **DSH 実装**: 機能ごとにサーバー側の状態と操作を実装する。必要な場合にだけ外部ランタイムへ接続し、資格情報はブラウザーに渡さない。
3. **実行画面**: DSH 内でプロジェクトとセッションを選び、開始、追加入力、進捗表示、中断、再開を行える。DSH と外部ランタイムの状態を混同しない。
4. **機能別検証**: ツール、差分、承認、履歴、モデル選択、メモリ、スキル、自動化などを実機で確認する。未対応機能は明示する。
5. **モバイル確認**: iPad とスマートフォンで操作し、サイドバー・チャット・外部実行画面が重ならないことを確認する。

## 現在の状態

最初の軽量機能として、T2 Code のプロンプトリンクの考え方を `dsh-mobile-maxxing` に実装した。現在のセッション ID と下書きだけを URL に入れ、開いた側が明示的に下書きを採用する。送信、権限変更、ワークツリー操作は行わない。共有対象は最大 8,000 文字で、非表示文字を除去してから提示する。追加の常駐処理はない。

Hermes の有界な永続メモリを参考にした任意パッケージ `dsh-bounded-memory` も追加した。DSH の既存 `AGENTS.md` 読み込みを再利用し、明示的な保存依頼がある場合だけ書き込む。ユーザー設定 1,375 文字、作業上の事実 2,200 文字で上限を固定し、上限超過時は自動削除しない。常駐サービスやポーリングはない。DSH の稼働中プロファイルは未変更。
