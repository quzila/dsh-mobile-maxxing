# T2 Code / Hermes Agent を DSH 内で利用するための設計メモ

## 対象

- T2 Code: <https://github.com/ashutoshpw/t2code>。Codex、Claude などの既存エージェントを操作する独立したアプリ。`docs/user/outside-agents.md` に OAuth 対応の MCP サーバーを公開する方法がある。
- Hermes Agent: <https://github.com/NousResearch/hermes-agent>。独立したエージェント実行環境。`website/docs/user-guide/features/` に ACP と OpenAI 互換 HTTP API の接続方法がある。

## 目標と境界

利用者は DSH の Web 画面内で両者の機能を選択・実行・観察できることを望む。既存の `dsh-mobile-maxxing` は DSH Web UI の表示と操作を変更するプラグインであり、外部エージェントのセッションや権限を管理する実装は持たない。接続機能は DSH サーバー側の別プラグインとして実装し、モバイル画面にはその状態と操作を表示する。

## 接続案

| 対象 | 公式に確認できる接続面 | DSH 側に必要なもの |
| --- | --- | --- |
| T2 Code | OAuth 対応 HTTP MCP。プロジェクト・スレッドの取得、開始、送信、停止、モデル一覧など | MCP クライアントと OAuth、権限別の操作、スレッドの表示と状態同期 |
| Hermes Agent | ACP (stdio)、OpenAI 互換 HTTP API | ACP または HTTP クライアント、セッション継続、ストリーム・ツール進捗・中断・承認の表示 |

T2 Code の MCP は外部エージェントに公開する操作の一部であり、T2 Code の全 UI 機能を公開するものではない。Hermes の ACP はエディター用途に合わせたツールセットで、cron やメッセージ配送などは対象外。したがって「すべて」を満たすには、両者の公開プロトコルだけで足りるか機能ごとに検証し、不足分は各プロジェクトの API か DSH 独自 UI で補う必要がある。

## 実装順と完了条件

1. **機能台帳**: T2 Code と Hermes の公開機能を列挙し、DSH 既存機能・接続可能・追加実装が必要・提供不可を区別する。利用不可を利用可能として表示しない。
2. **サーバー接続**: 資格情報をブラウザーに渡さず DSH サーバー側に保管する。接続・再接続・失効・権限不足を UI で区別する。T2 Code は初回 OAuth 承認が必要。
3. **実行画面**: DSH 内で外部プロジェクトとセッションを選び、開始、追加入力、進捗表示、中断、再開を行える。外部側の状態を DSH の状態と混同しない。
4. **機能別検証**: ツール、差分、承認、履歴、モデル選択、メモリ、スキル、自動化などを実機で確認する。未対応機能は明示する。
5. **モバイル確認**: iPad とスマートフォンで操作し、サイドバー・チャット・外部実行画面が重ならないことを確認する。

## 現在の状態

この文書は調査と設計の記録。T2 Code と Hermes Agent の接続プラグイン、認証、実行画面は未実装。DSH の稼働中プロファイルも未変更。
